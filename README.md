# Robotics for People

**A free, open, living textbook for robotics, the field without edges.** Written for people, and readable by AI agents.

**[Read it online](https://markus-learning.github.io/ROBOTICS-for-PEOPLE/)** · [Explore the graph](https://markus-learning.github.io/ROBOTICS-for-PEOPLE/explore/) · [Start here](00_Introduction/Learning_Paths.md) · [The map of robotics](00_Introduction/Subfield_Atlas.md) · [Help write it](00_Introduction/Frontier.md) · [For agents: `llms.txt`](https://markus-learning.github.io/ROBOTICS-for-PEOPLE/llms.txt)

Robotics is not one subject. It is where mathematics, mechanics, electronics, computing, biology, design and ethics meet. It grew up in manufacturing, where more than five million industrial robots now work (IFR, 2025), and it keeps reaching into places nobody planned for: surgery and farming, the deep sea and orbit, prosthetics, swarms, machines made of soft or living materials, and ideas nobody has named yet. This textbook maps that whole territory, from what a robot is to the open problems at the edge of the field, with manufacturing as its home ground, and it grows every time someone adds a note.

## Manufacturing first

Manufacturing is where robots earn their living, so it gets first-class treatment:

- [Manufacturing](08_Robot_Types_and_Applications/02_Manufacturing/Manufacturing.md): the 2025 numbers, the robot cell, takt time and OEE, and what AI does and does not yet do in factories.
- [Industrial arms](08_Robot_Types_and_Applications/01_Robot_Types/03_Industrial_Arms/Industrial_Arms.md), [cobots and safety](08_Robot_Types_and_Applications/01_Robot_Types/18_Collaborative_Robots/Collaborative_Robots.md), [work cell design](08_Robot_Types_and_Applications/02_Manufacturing/Robot_Work_Cell_Design.md), [PLCs](08_Robot_Types_and_Applications/02_Manufacturing/Programmable_Logic_Controllers.md), [robotic welding](08_Robot_Types_and_Applications/02_Manufacturing/Robotic_Welding.md) and [machine vision](08_Robot_Types_and_Applications/02_Manufacturing/Machine_Vision_in_Manufacturing.md).
- The manufacturing notes work real factory problems: cycle times, payloads, weld heat input, inspection error rates and safety distances.

## Read it your way

- **On the web.** [markus-learning.github.io/ROBOTICS-for-PEOPLE](https://markus-learning.github.io/ROBOTICS-for-PEOPLE/) has search, backlinks, and an index page for every tag, level, status, type and subfield. Every note opens with its level, its subfields, what to read first and what comes next.
- **As a map.** [Explore](https://markus-learning.github.io/ROBOTICS-for-PEOPLE/explore/) shows the whole textbook as a 3D globe or a 2D map. Colour it by subfield, level or status, filter it, search it, and trace any note's prerequisites back to first principles.
- **In Obsidian.** Clone the repo and open the folder as a vault. The vault settings are included: enable community plugins when Obsidian asks, and the [Dataview](https://blacksmithgu.github.io/obsidian-dataview/) plugin makes the [dashboard](00_Introduction/Robotics_Vault_Dashboard.md) and the per-note lists live.
   ```bash
   git clone https://github.com/MARKUS-LEARNING/ROBOTICS-for-PEOPLE.git
   ```
- **On GitHub.** Every note is plain Markdown. The [Subfield Atlas](00_Introduction/Subfield_Atlas.md), [Learning Paths](00_Introduction/Learning_Paths.md) and [Frontier](00_Introduction/Frontier.md) are generated as plain Markdown too, so they read well here.
- **With an AI agent.** Give it the site's [`llms.txt`](https://markus-learning.github.io/ROBOTICS-for-PEOPLE/llms.txt). From there it can reach:
  - [`llms-full.txt`](https://markus-learning.github.io/ROBOTICS-for-PEOPLE/llms-full.txt): every note;
  - a file per chapter;
  - [`graph.json`](https://markus-learning.github.io/ROBOTICS-for-PEOPLE/graph.json): every note with its type, level, subfields, status and prerequisites, the links between notes, and the notes still to write;
  - the raw source of any note.

## How the textbook builds itself

Every note carries the same kind of metadata ([schema](00_Introduction/Vault_Taxonomy_Guide.md#frontmatter-schema-v2)):

```yaml
type: method                 # concept, method, component, robot-type, tool, tutorial, lab, overview, ...
level: intermediate          # beginner, intermediate, advanced, research
subfield: [kinematics-dynamics, manipulation]   # from the Subfield Atlas
status: keystone             # stub, draft, reviewed, keystone
prerequisites: ["[[Forward_Kinematics]]", "[[Jacobian_Matrix]]"]
```

From that metadata, every change to the notes rebuilds:
- the [Subfield Atlas](00_Introduction/Subfield_Atlas.md), a map of robotics in five groups (the core stack, robot bodies, domains, society, and the frontier);
- the [Learning Paths](00_Introduction/Learning_Paths.md);
- the [Frontier](00_Introduction/Frontier.md);
- the website;
- the agent files.

`tools/vault.py` reads the vault the way Obsidian does: same links, same tags, and checked against Obsidian itself through the [Obsidian CLI](https://help.obsidian.md/cli). Continuous integration checks every pull request:
- notes against the schema and the [tag vocabulary](tools/tags.yml);
- that prerequisites never form a loop;
- that generated pages are current;
- that the website has no dead links;
- that **the number of broken links never goes up**.

## Help write it

The [Frontier](00_Introduction/Frontier.md) is the to-do list: topics other notes already link to, ranked by how many are waiting for them, plus the parts of robotics that are barely covered. Pick one, write it, and open a pull request. [CONTRIBUTING.md](CONTRIBUTING.md) has the details.

```bash
pip install pyyaml
python3 tools/vault.py lint           # check your note
python3 tools/vault.py pages --write  # rebuild the Atlas, Paths and Frontier
```

## Methods

MIT licensed. I started this textbook to teach myself robotics, and I share it so others can learn too, especially people who build and run robots in manufacturing.

Notes are researched and drafted with Claude, then checked: equations and worked examples are recomputed, code is run, and every cited source is verified by `tools/check_sources.py`. Corrections and new notes are welcome, above all from the factory floor.
